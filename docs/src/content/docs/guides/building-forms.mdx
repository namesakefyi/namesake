import { FileTree } from '@astrojs/starlight/components';

Once you have [added new PDFs](/guides/new-pdfs) to the codebase, you are ready to create an interactive [form](https://namesake.fyi/forms).

## Set up your form folder

Add a new folder to `web/src/content/forms` with the following structure:

<FileTree>

- my-form
  - e2e.spec.ts
  - index.ts # Steps, PDFs, and instructions
  - index.yml # Static metadata (title, description, jurisdiction, etc.)

</FileTree>

## Define form metadata

Inside `index.yml`, fill out static metadata for the form, such as the title, description, and costs.

```yml wrap
# index.yml
title: "Court Order: Massachusetts"
description: "If you live in Massachusetts and want to legally update your name, this is the place to start."
jurisdiction: "ma"
category: "court-order"
costs:
  - title: "Filing fee"
    amount: 150
    required: true
  - title: "Surcharge fee"
    amount: 15
    required: true
```

## Write the steps

Inside `index.ts`, import `defineForm` and list the steps in the order people see them. Each step has an `id`, a `title`, and a `body` of questions and content.

```ts
// index.ts
import { defineForm } from "#lib/forms/defineForm";
import { node } from "#lib/forms/steps";

export default defineForm({
  steps: [
    {
      id: "new-name",
      title: "What is your new name?",
      description: "Type it exactly as you want it to appear.",
      body: [node.name("newName")],
    },
    {
      id: "contact-info",
      title: "What is your contact information?",
      body: [
        node.phone("phoneNumber"),
        node.email("email"),
      ],
    },
  ],
  // ...
});
```

### Choose a question type

Every question and block comes from `node`, and each matches a component. Options marked `?` are optional.

| Builder | Component | Saves |
|---|---|---|
| `node.shortText(name, { label?, size? })` | `ShortTextField` | A line of text |
| `node.longText(name, { label? })` | `LongTextField` | A paragraph of text |
| `node.number(name, { label?, min?, currency?, defaultValue? })` | `NumberField` | A number; `currency: true` shows dollars |
| `node.memorableDate(name, { label? })` | `MemorableDateField` | A date, such as a date of birth |
| `node.checkbox(name, { label })` | `CheckboxField` | `true` or `false` |
| `node.yesNo(name, { label?, yesLabel?, noLabel?, extraChoices? })` | `YesNoField` | `true` or `false`, or an extra choice |
| `node.radioGroup(name, { label?, options, extraChoices? })` | `RadioGroupField` | One option's key |
| `node.checkboxGroup(name, { label?, options, extraChoices? })` | `CheckboxGroupField` | A list of option keys |
| `node.comboBox(name, { label?, source, placeholder? })` | `ComboBoxField` | One value from `source`: `"countries"`, `"jurisdictions"`, or `"maritalStatus"` |
| `node.phone(name, { label? })` | `PhoneField` | A phone number |
| `node.email(name, { label? })` | `EmailField` | An email address |
| `node.languageSelect(name)` | `LanguageSelectField` | A language |
| `node.name(type)` | `NameField` | First, middle, and last name for `type`: `"newName"`, `"oldName"`, `"mothersName"`, `"fathersName"`, or `"previousSocialSecurityCardName"` |
| `node.address(type, { address2?, county? })` | `AddressField` | An address for `type`: `"residence"`, `"mailing"`, `"parent1"`, or `"parent2"`; only residence and mailing take `address2` and `county` |
| `node.pronounSelect()` | `PronounSelectField` | Pronouns, plus other pronouns when "other" is picked |
| `node.repeatingEntry(name, { label?, min, max?, itemLabel, size? })` | `RepeatingEntry` | A list of short answers, each labeled `itemLabel` and its number |

Every question also takes these options:

| Option | Does |
|---|---|
| `when` | Shows the question only while the condition is true |
| `reviewLabel` | Labels the answer on the review page |
| `description` | Adds help text under the question (not on `node.checkbox`, `node.languageSelect`, `node.name`, `node.address`, or `node.pronounSelect`) |

`extraChoices` adds "Prefer not to answer" (`"preferNotToAnswer"`) and, on `node.yesNo`, "I don't know" (`"dontKnow"`).

Give each question a `label`. If a step or a titled subsection asks a single question, leave out its label and the title is used instead.

For choices, label every option. The keys are what gets saved; the labels are what people see:

```ts
node.radioGroup("courtType", {
  options: { Civil: "Civil Court", Supreme: "Supreme Court" },
}),
```

### Label answers on the review page

The review page lists each answer under its label. When a label only makes sense next to its question, add a `reviewLabel`:

```ts
node.shortText("birthplaceCity", {
  label: "City",
  reviewLabel: "City of birth",
}),
```

### Skip a step

Add `when` to a step to include it only for some answers:

```ts
{
  id: "birth-certificate",
  title: "Do you want to update your Rhode Island birth certificate?",
  when: (data) =>
    data.birthplaceCountry === "US" && data.birthplaceState === "RI",
  body: [/* ... */],
},
```

A condition is a function of the answers so far. Check for `true` or `false` explicitly: `data.isCurrentlyUnhoused !== true` also includes people who haven't answered yet, while `data.isCurrentlyUnhoused === false` only includes people who answered no.

### Ask follow-up questions

Put follow-up questions in a `node.subsection` with a `when`. They appear only once the earlier answer calls for them, and are left off the review page and PDFs otherwise:

```ts
import { node } from "#lib/forms/steps";

body: [
  node.yesNo("hasUsedOtherNameOrAlias"),
  node.subsection(
    [node.longText("otherNamesOrAliases", { label: "Other names or aliases" })],
    {
      title: "Please list all names you haven't previously listed.",
      when: (data) => data.hasUsedOtherNameOrAlias === true,
    },
  ),
],
```

A single question can also take its own `when`.

### Add guidance

Some nodes add content that saves nothing:

| Builder | Shows |
|---|---|
| `node.banner(content, { variant?, when? })` | A callout. `content` is markdown, so it can include links, **bold** text, and lists (but not a link inside bold text). `variant` is `"info"`, `"success"`, `"warning"`, or `"error"` |
| `node.subsection(children, { title?, when? })` | A group of questions and content, with an optional title |
| `node.display(Component, { props? })` | A component, such as the shared `NameChangeReasonBanner` |

```ts
node.banner(
  "Attach a copy of each prior court order or marriage license to your petition.",
  { when: (data) => data.hasPreviousNameChange === true },
),
```

If the same copy appears more than once in a form, for example in a banner and in the instructions, define it once at the top of `index.ts`.

### Add a new field

If a question saves an answer that no form has asked for before, add it to `web/src/constants/fields.ts` with its `name` and `type`. For a fixed set of answers, also list its `values`:

```ts
{
  name: "incomePeriod",
  type: "string",
  values: ["weekly", "biweekly", "monthly", "yearly"],
},
```

## Add PDFs and instructions

Finish `index.ts` with the PDFs to fill and the instructions for the cover page of the download:

```ts
export default defineForm({
  steps: [/* ... */],
  pdfs: [
    { pdfId: "cjp27-petition-to-change-name-of-adult" },
    { pdfId: "cjp34-cori-and-wms-release-request" },
  ],
  downloadTitle: "Massachusetts Court Order",
  instructions: [
    "Review all documents carefully.",
    {
      text: "Attach a copy of each prior court order or marriage license to your petition.",
      when: (data) => data.hasPreviousNameChange === true,
    },
  ],
});
```

A PDF or instruction with a `when` is only included for matching answers.

## Render the form

In your guide, render `FormContainer` with your form's `slug`:

```mdx
// court-order.mdx

import FormContainer from "#components/forms/FormContainer/FormContainer.astro"

## Fill out forms

<FormContainer slug="court-order-ma" />
```

## Connect PDF fields

Now that your form collects data, go back to `web/src/content/pdfs` and update the resolver values in `index.ts` with the matching fields from `data`:

```ts {4-9}
// index.ts
export default definePdf<PdfFieldName>({
  // ...
  resolver: (data) => ({
    petitionerFirstName: data.newFirstName,
    petitionerMiddleName: data.newMiddleName,
    petitionerLastName: data.newLastName,
    // Map remaining PDF fields to form data...
  }),
});
```

## Test the form

Run the unit tests with `pnpm exec vitest run` and fix anything they report for your form.

Add end-to-end tests to `e2e.spec.ts` covering the full form flow. Look at existing form specs in `web/src/content/forms` for examples of how to fill in steps, verify the review page, and confirm PDF output.
