Once you have [added new PDFs](/guides/new-pdfs) to the codebase, you are ready to create an interactive [form](https://namesake.fyi/forms).

## Set up your form folder

Add a new folder to `web/src/content/forms`. Put a state or territory form inside its jurisdiction's folder, such as `ma/court-order`. Put a federal form at the root, such as `social-security`. The folder path becomes the form's URL: `/forms/ma/court-order`.

Each form has three files, which load at different times:

<FileTree>

- ma
  - my-form
    - index.ts # Title, description, and costs
    - steps.ts # The questions
    - download.ts # The PDFs to fill and the cover page instructions
    - e2e.spec.ts

</FileTree>

## Describe the form

In `index.ts`, give the form its title, description, category, and costs. This is what the forms page and the form's first screen show.

```ts
// index.ts
import { defineForm } from "#lib/forms/defineForm";

export default defineForm({
  title: "Court Order: Massachusetts",
  description:
    "If you live in Massachusetts and want to legally update your name, this is the place to start.",
  category: "court-order",
  costs: [
    { title: "Filing fee", amount: 150, required: true },
    { title: "Surcharge fee", amount: 15, required: true },
  ],
});
```

To keep a form off the forms page while it's still reachable by its URL, add `unlisted: true`.

## Write the steps

In `steps.ts`, list the steps in the order people see them. Each step has an `id`, a `title`, and an array of `questions`.

```ts
// steps.ts
import { defineSteps } from "#lib/forms/defineForm";
import { q } from "#lib/forms/questions";

export default defineSteps([
  {
    id: "new-name",
    title: "What is your new name?",
    description: "Type it exactly as you want it to appear.",
    questions: [q.name("newName")],
  },
  {
    id: "contact-info",
    title: "What is your contact information?",
    questions: [q.phone("phoneNumber"), q.email("email")],
  },
]);
```

### Choose a question type

Pick the question that matches the answer you need, such as `q.yesNo` for a yes-or-no answer or `q.address` for an address. Every question and its options are listed in [`questions.ts`](https://github.com/namesakefyi/namesake/blob/main/web/src/lib/forms/questions.ts). To see how each one looks, browse the form components in [Storybook](https://storybook.namesake.fyi).

Give each question a `label`. If a step or a titled subsection asks a single question, leave out its label and the title is used instead.

For `q.radioGroup` and `q.checkboxGroup`, label every option. The keys are what gets saved; the labels are what people see.

### Label answers on the review page

The review page lists each answer under its label. When a label only makes sense next to its question, add a `reviewLabel`:

```ts
q.shortText("birthplaceCity", {
  label: "City",
  reviewLabel: "City of birth",
}),
```

### Skip a step

Add `when` to a step to include it only for some answers:

```ts
{
  id: "birth-certificate",
  title: "Do you want to update your Rhode Island birth certificate?",
  when: (data) =>
    data.birthplaceCountry === "US" && data.birthplaceState === "RI",
  questions: [/* ... */],
},
```

A condition is a function of the answers so far. Check for `true` or `false` explicitly: `data.isCurrentlyUnhoused !== true` also includes people who haven't answered yet, while `data.isCurrentlyUnhoused === false` only includes people who answered no.

### Ask follow-up questions

Put follow-up questions in a `q.subsection` with a `when`. They appear only once the earlier answer calls for them, and are left off the review page and PDFs otherwise:

```ts
import { q } from "#lib/forms/questions";

questions: [
  q.yesNo("hasUsedOtherNameOrAlias"),
  q.subsection(
    [q.longText("otherNamesOrAliases", { label: "Other names or aliases" })],
    {
      when: (data) => data.hasUsedOtherNameOrAlias === true,
      title: "Please list all names you haven't previously listed.",
    },
  ),
],
```

A single question can also take its own `when`.

### Add guidance

Add a banner, a costs table, or another block that saves nothing alongside the questions. The blocks are listed alongside the questions in [`questions.ts`](https://github.com/namesakefyi/namesake/blob/main/web/src/lib/forms/questions.ts).

```ts
q.banner(
  "Attach a copy of each prior court order or marriage license to your petition.",
  { when: (data) => data.hasPreviousNameChange === true },
),
```

If the same copy or condition is used in both `steps.ts` and `download.ts`, for example in a banner and in the instructions, define it once in a `conditions.ts` next to them and import it into both.

### Name the answers

The name you give a question, such as `"incomePeriod"`, is where its answer is saved. Answers are shared across forms by name, so a name entered in one form is filled in on the next.

- **An answer only your form asks for** needs nothing else. Pick a name no other form uses.
- **An answer another form already asks for** should use that form's name, so people don't have to answer twice. If that name isn't in `SHARED_FIELDS` yet, move it into [`web/src/constants/fields.ts`](https://github.com/namesakefyi/namesake/blob/main/web/src/constants/fields.ts).

Name yes-or-no answers as questions, starting with a word like `is`, `has`, or `should`, such as `hasPreviousNameChange`.

For a yes-or-no question that also offers "Prefer not to answer" or "I don't know", add `extraChoices`:

```ts
q.yesNo("isHispanicOrLatino", {
  label: "Are you Hispanic or Latino?",
  extraChoices: ["preferNotToAnswer"],
}),
```

## Fill the PDFs

In `download.ts`, list the PDFs to fill, how to fill each one, and the instructions for the download's cover page. Import each PDF from `web/src/content/pdfs`.

```ts
// download.ts
import cjp27 from "#content/pdfs/ma/cjp27-petition-to-change-name-of-adult";
import { defineDownload } from "#lib/forms/defineForm";
import { formatDateMMDDYYYY } from "#lib/utils/formatDateMMDDYYYY";

export default defineDownload({
  title: "Massachusetts Court Order",
  instructions: [
    "Review all documents carefully.",
    {
      text: "Attach a copy of each prior court order or marriage license to your petition.",
      when: (data) => data.hasPreviousNameChange === true,
    },
  ],
  pdfs: [
    {
      pdf: cjp27,
      fill: (data) => ({
        petitionerFirstName: data.oldFirstName,
        petitionerLastName: data.oldLastName,
        dateOfBirth: formatDateMMDDYYYY(data.dateOfBirth),
        county: undefined,
        // ...every other field in the PDF's schema.ts
      }),
    },
  ],
});
```

`fill` returns a value for every field in the PDF's `schema.ts`. Write `undefined` for a field the form leaves blank.

A PDF or instruction with a `when` is only included for matching answers.

The `title` names the downloaded file and appears on its cover page.

## Render the form

In your guide, render `FormContainer` with your form's `formId`, which is its folder path including the jurisdiction:

```mdx
// court-order.mdx

import FormContainer from "#components/forms/FormContainer/FormContainer.astro"

## Fill out forms

<FormContainer formId="ma/court-order" />
```

## Test the form

Run the unit tests with `pnpm exec vitest run` and fix anything they report for your form.

Add end-to-end tests to `e2e.spec.ts` covering the full form flow. Look at existing form specs in `web/src/content/forms` for examples of how to fill in steps, verify the review page, and confirm PDF output.
